## [2667. Create Hello World Function](https://leetcode.com/problems/create-hello-world-function/description/?envType=study-plan-v2&envId=30-days-of-javascript)
**Difficulty: Easy** | **Topic: Closure** 

Since this question and the next 3 are about **Closures**, it's important we get an understanding of what it is before we even start doing the question.

In JavaScript, every function is a closure by definition. A closure is simply the combination of a function and the "lexical environment" in which it was declared. That environment includes any variables available to the function at the time of its creation—including global variables like myName. **In other words, every scope, has access to it's outside scope**

For example:
```js
const myName = 'Kyle'
function printName() { 
    console.log(myName)
}

printName()
``` 

> This code is a closure because `printName` "closes over" the global scope to access `myName`.

However, developers usually only use the word "closure" when a function is nested inside another function and "captures" a variable from that parent function.

For example:
```js
function makeFunc() {
  const name = 'Kyle';
  return function() { console.log(name); }; // This is what people "usually" call a closure
}
```

Another example:
```js
function outerFunction(outerVariable) {
    return function innerFunction(innerVariable) {
        console.log('Outer Variable: ' + outerVariable);
        console.log('Inner Variable: ' + innerVariable);
    };
}

const newFunction = outerFunction('outside');
newFunction('inner');
// output:
// Outer Variable: outside
// Inner Variable: inner
```
In this specific code, the closure is created the moment you define `innerFunction` inside `outerFunction`. Here is the step-by-step breakdown:

When we run `const newFunction = outerFunction('outside')`, the `outerFunction` starts and finishes. It sets `outerVariable` to `'outside'` and then returns the inner function.

- Normally: In many languages, once a function finishes, its local variables (like outerVariable) are deleted from memory.
- In JavaScript: Because `innerFunction` is defined inside and uses `outerVariable`, it creates a **closure**. It "closes over" that variable and keeps it alive. (this should be the aha moment xD)

At this point, `newFunction` is just the `innerFunction` code (since that is what we returned), but it is carrying a secret "backpack" that contains the variable `outerVariable = 'outside'`.

When we call `newFunction('inner')`, you are finally running that inner code.

- It looks for `innerVariable` and finds it in its own arguments (`'inner'`).
- It looks for `outerVariable`. It doesn't find it inside itself, so it looks in its backpack (the closure).
- It finds `'outside'` there, even though the `outerFunction` that created it ended a long time ago.

To sum it up, **closure** is the persistent link between the inner function and the scope where it was born. It allows innerFunction to "remember" the environment of outerFunction even after outerFunction has officially "closed."

Another important concept to understand is **Hoisting**.
Take this code as an example:
```js
function sumFunc(a, b) {
  return a + b;
}

const sumConst = (a, b) => a + b;

console.log(`sumFunc(1, 2) -> ${sumFunc(1, 2)}`);
console.log(`sumConst(3, 4) -> ${sumConst(3, 4)}`);
```

This code will print what we expect, `sumFunc(1, 2) => 3` and `sumConst (3, 4) => 7`. As we know in JS, all our code runs from top to bottom in order. However, with Hoisting, we can move functions below the `console.log` line (where the function is called) and our code will still work. 

For example, will still give us the same output.
```js
const sumConst = (a, b) => a + b;

console.log(`sumFunc(1, 2) -> ${sumFunc(1, 2)}`);
console.log(`sumConst(3, 4) -> ${sumConst(3, 4)}`);

function sumFunc(a, b) {
  return a + b;
}
```

This is because the function `sumFunc`, will take it and move it (hoist it) to the very top of the file. It does this will all the functions with the `function` keyword. 

However, this doesn't work with the `const` or `let` keyword as their not hoisted. We will get a reference error if our arrow function is under our `console.log` in the code above.

In JS, we have three different ways of assigning a variable. We could use `var`, `let`, or `const`. 

- `var`
Back in the old days, JS only had one way of declaring a variable and that was with the `var` keyword which was **function scoped** but people later ran into problems. Therefore `let` and `const` variables were created to be **blocked scoped** rather than functioned scoped.

The key difference between function and blocked scoped: 

- function scope variable: available anywhere in the function it's declaried 
- blocked scoped variable: only available in the block it's declaired in. For example, an `if` or a `while` loop would be a block and blocked variables only have access inside those blocks. Not anywhere else outside.

Code example:
```js
if (true) {
  var varVariable = "This is true";
}

console.log(varVariable);

if (true) {
  let letVariable = "This is true";
}

console.log(letVariable);

// the first console.log prints "This is true" 
// the second console.log prints a ReferenceError since it's "not defined"
// the same would happen if we use const instead of let
```

Therefore, that is why in our solution snippet above, we used the keyword `const` rather than `let` for delcaring the anomynous function. 

In the code template the leetcode gave us, we see `...args`, which is a **spread operator**.
```js
/**
 * @return {Function}
 */
const createHelloWorld = function() {
    return function(...args) {
    }
}
```

Here is a code example of a spread operator being used:
```js
let a = [1, 2];
let b = [3, 4];
console.log([...a, ...b])
// logs [1, 2, 3, 4]
```

What a spread opertor does, it **expands every values in an iterable**.

We can we spread operators as functions parameters as well.

```js
function add(...args) {
  console.log(args[0] + args[1]);
}

add(8, 2);
// args is [8, 2]
// logs 10
```

Therefore, our final solution is 
```js
/**
 * @return {Function}
 */
const createHelloWorld = function() {
    return function(...args) {
        return 'Hello World!'
    }
}
/**
 * const f = createHelloWorld();
 * f(); // "Hello World"
 */
```
